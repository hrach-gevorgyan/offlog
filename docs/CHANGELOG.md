# Offlog — Changelog

The single source of truth for version history — this used to be duplicated
across `TECH.md` (technical detail) and the root `README.md` (short
highlights), which had drifted in coverage (TECH.md's table was more
complete). Consolidated here 2026-07 as part of the documentation cleanup;
both `README.md` and `docs/TECH.md` now link here instead of keeping their
own copy. New entries go at the top, one row per released version.

This table keeps the newest **10** releases in full detail. Older releases
are compressed to one line each in
[archive/changelog-archive.md](archive/changelog-archive.md) (git still has
every full diff; that folder also holds the full maintenance-pass log,
moved out of MAINTENANCE.md 2026-07-20) — split out 2026-07 once this
file's default-loaded size grew large enough to matter. When adding a new
entry, move the oldest row here into the archive (compressed to one line)
once this table exceeds 10 rows, so it stays roughly the same length
release over release. Archive weekly, or whenever it's due, not on a fixed
per-release schedule.

| **6.0.1** | **Maintenance pass (17th run)**, pulled forward right after v6.0.0's feature batch (file attachments, recurrence fix, unified search, tag colors) landed in one session — no schema/sync/storage-format changes. Two real, verified findings, both fixed: `db.ts`'s `getRecentlyModifiedTasks()` was dead code, orphaned since the 5.9.0 redesign removed the Sidebar "Recent" section it fed; `GlobalSearch.svelte` re-declared its own `'title'\|'tags'\|'body'\|'checklist'` union instead of importing the already-exported `TaskSearchMatch` type from `db.ts` — deduped. `store.ts`'s `tasks` writable has an unnecessarily-wide `export` (only its derived `projectTasks` is used elsewhere) — reported, left alone at owner's call, trivial/zero-value. `npx knip` also flagged 4 deps and 4 Svelte files as unused; all hand-verified as real, dynamically-imported code (false positives, consistent with this project's established experience with the tool on Svelte/Tauri). `npm audit`: 0 vulnerabilities. Build-output secret-leakage gate re-checked against a real `.env.local` — clean. Dist size: 1.2MB, unchanged from the v5.8.2 baseline despite the whole v6.x feature batch landing since |
| **6.0.0** | **File attachments, recurrence hardening, unified search, tag colors.** File attachments (v6.8.0): images/PDFs/spreadsheets/any file (except HEIC/HEIF) attach to a task, 10MB/file and 10/task caps, images downscaled to ~1600px and re-encoded to JPEG client-side before saving; bytes live in PouchDB's native `_attachments` on the task doc itself (single database, no separate sync channel — see DECISIONS.md for why a second db was considered and rejected), so attachments ride the existing sync with zero new code. Recurrence robustness pass (v6.9.0): fixed a real bug where monthly recurrence overflowed past shorter months (Jan 31 due date rolled to Mar 3 instead of Feb 28/29) — `advanceDate()` now clamps to the target month's real last day; DST reminder-shifting and long-offline-gap completion behavior were audited and confirmed already correct. Unified search (v6.10.0): Global Search now also matches checklist item text, not just title/tags/notes, and shows *why* a result matched when the title itself doesn't contain the query. Tag color picker (v6.11.0): tags already got a deterministic hash color automatically — added a manual override (swatch picker in Settings → Organize → Manage Tags), with an "Auto" reset back to the hash color. Also this release: the mobile sidebar could be collapsed to the desktop-only icon rail by mistake (now gated to desktop). No schema-breaking changes — `TaskDoc` gains `attachments`, existing docs are unaffected |
| **5.9.0** | **Sidebar + CardDetail visual redesign** — collapsible + resizable sidebar (new), CardDetail's optional fields (Repeat/Reminder, Checklist, Custom Fields, Related, Notes) consolidated under one manually-opened "Extras" panel instead of scattered always-visible blocks. Sidebar: icon-only footer row (Time Travel/Recycle/Settings/Sync) shared between collapsed and expanded modes; sync status shown via the icon's own muted color (green/red/indigo/amber for synced/error/syncing/conflict) instead of a separate dot+badge, clicking it now opens Settings' Sync category rather than triggering a sync directly; active-state highlighting unified and toned down across nav/space/project rows (plain bold text or a light bordered card, no more loud accent-tinted pills); removed the Recent quick-resume section and the per-space project-count badge (owner calls, after live review). Two real bugs found and fixed along the way: `CalendarPicker`'s popover got clipped inside CardDetail's new scrollable modal (now `position: fixed` with measured coordinates, same pattern as ListView's column menu); Dashboard/Focus/Agenda never cleared `activeProjectId`, so the sidebar kept highlighting the last-open project even while viewing one of those three pages. Minor bump (not patch) given the scope — no schema/sync/storage-format changes |
| **5.8.3** | **Maintenance pass (16th run)** — no schema/sync/storage-format changes, per MAINTENANCE.md's hard constraints. Real fix: `notifications.ts`'s `fireTauriNotification()` and `catchUpTauri()`'s stale-reminder branch both silently swallowed `updateTask()` failures via a bare `.catch(() => {})`, unlike `fireWebNotification()`'s already-fixed equivalent (the same bug class behind the v5.4.6 rev-conflict race and a v5.7.2-era flaky test) — the Tauri path just never got the same fix when it was added later. Also found and fixed: `TaskHistoryPanel.svelte` had its own hand-copied `FIELD_LABEL`/`fmtVal`/`describeField`/`hasRealChange`, duplicating `logFormat.ts` despite that file's own header comment saying it was extracted specifically to prevent this — it had already drifted (missing the `'name'` rename case, missing the `isEmpty()` no-op filter from `logFormat.ts`'s 2026-07-18 fix, so a no-op checklist/custom-field diff could still show a false "Checklist updated" here after Time Travel had already stopped showing it); now imports the shared logic instead. Housekeeping: removed `export` from 6 module-internal-only symbols flagged by `knip` and individually hand-verified (not trusting the tool's say-so) — `DEFAULT_SYNC_URL`, `reresolveHost`, `FIELD_LABEL`, `MaintStepKey`, `UpdatePhase`, `UpdateState`; updated MAINTENANCE.md's stale unsafe-Rust-block checklist (missed C8's `secure_storage.rs` DPAPI calls) and its dist-size drift ledger (1.1MB → 1.2MB, ~9% growth, under threshold, explained by C8/App Lock work). `SettingsPanel.svelte`'s size (2063 lines) and a handful of unverified `knip` export flags were surfaced but deliberately left alone — real risk/effort mismatch for a routine pass, not a defect |
| **5.8.2** | **Monthly Dependabot batch** — 6 low-risk patch/minor bumps, all merged after green CI: `jsdom` 29.1.1→30.0.0, `svelte-check` 4.7.3→4.7.4, `@types/node` 26.1.1→26.1.2, `svelte` 5.56.7→5.56.8 (offlog-app); `mdns-sd` 0.20.2→0.20.3 (offlog-desktop); `actions/cache` 4→6 (github_actions). No functional changes. First release under ROADMAP.md's new bugfix/audit track (2026-07-28), which folds routine dependency batches into a patch version rather than merging them ad hoc |
| **5.8.1** | **C8 — the stored sync password is now encrypted at rest, per-platform** instead of plain `localStorage` (a real CodeQL finding). Rejected an app-level "encrypt with a key that's also in localStorage" scheme as security theater; used each platform's real primitive instead — Android via the already-installed `capacitor-native-biometric` plugin's Keystore-backed `setCredentials`/`getCredentials` (previously unused, only `verifyIdentity` was called), Windows via a new `windows` crate dependency for DPAPI (`CryptProtectData`/`CryptUnprotectData`, ties ciphertext to the current Windows user account) through two new Tauri commands (`store_sync_secret`/`get_sync_secret`, `secure_storage.rs`). Plain web build keeps `localStorage` — no browser-level secure-storage primitive exists, and it's already a dev/test surface, not production use. `getSyncCredentials()`/`setSyncCredentials()` are async now; existing installs migrate silently from the old plaintext keys, no re-pairing needed. Also this release, from live UI feedback — the update-modal's release notes rendered raw markdown text instead of formatted headings/bullets; the Sync nav badge and sidebar footer conflict badge both rendered as stretched ovals instead of circles (root cause was CSS specificity, `.nav-item span{flex:1}` beating the badge's own class rule, not the size values); the sidebar's Sync button had a status dot, conflict badge, icon, and label all crammed into one small corner, simplified to icon/label tinting instead of a separate dot; the "Connect a device" PC pairing modal showed a bare button with zero context on first open. CodeQL housekeeping: `codeql.yml` was missing a paths-ignore so it re-ran on doc-only pushes; added `.codeqlignore` (node_modules/target/dist) since the config-file's paths-ignore alone didn't reliably suppress findings inside bundled Capacitor plugin source under `build-mode: manual`. Docs: the owner-vetted Post-Done feature list moved from IDEAS.md (open questions) to ROADMAP.md (committed backlog), where it actually belongs |
| **5.8.0** | **`offlog-desktop` fully adopts NyxDB, real Apache CouchDB removed entirely** — not another experiment, a permanent replacement. Full history in `docs/DECISIONS.md`'s NyxDB entries: a same-day trial found the protocol/size win real (~10x smaller installer, ~8x smaller installed footprint) but surfaced real bugs; round two shipped with every known fix baked in from the start, plus two real NyxDB server bugs found live and fixed same-day by the owner (`_bulk_get` misreporting live revisions as deleted — hit on every first device pairing; a fresh database's first document getting an invisible `seq=0`). Verified with a full scenario matrix afterward: two-host LAN detection, real conflict creation + resolution, offline-write/reconnect auto-resume, uninstall/reinstall identity + data persistence, and a realistic multi-device merge — all clean. Codebase-wide cleanup to match: CouchDB-era comments/history removed from `offlog-desktop`'s Rust and `offlog-app`'s TypeScript (kept only where naming the CouchDB *protocol* is still technically necessary), `VITE_COUCH_*` env vars and internal constants renamed to `VITE_SYNC_*`/`DEFAULT_SYNC_*`, `fetch-couchdb-win.ps1` replaced by `fetch-nyxdb-win.ps1`. Also this release: CodeQL findings addressed — `ci.yml`/`desktop-ci.yml` now declare explicit least-privilege `permissions: contents: read`; the sync-password cleartext-storage finding is a known local-first tradeoff, dismissed with justification and scheduled as ROADMAP.md's new C8 rather than patched ad hoc — minor version bump (not patch) since this is a real architectural swap, not a bugfix release |
| **5.7.9** | **Real bugs from live-testing v5.7.6/5.7.7's new updater/quiet-hours features**, plus a batch of smaller fixes. Quiet hours: queued reminders all computed to fire at the exact same window-end instant — a real backlog could hit Android/Windows notification queues as a simultaneous burst, some of which throttle/collapse bursts rather than showing each one; `notifications.ts`'s `applyQuietHours()` now takes a `staggerIndex` (15s apart per reminder) applied across every scheduling path, 2 new tests. Kanban drag-and-drop: touch-drag was writing into `dragTask`, the same variable the desktop mouse-drag path guards on — if a touch sequence ever ended without `touchend`/`touchcancel` firing (OS taking over the gesture for its own edge-swipe/scroll handling mid-drag), `dragTask` stayed stuck non-null with nothing left watching it, fixable only by a full app restart. Touch and mouse drag now track fully separate state, plus a 15s watchdog and a document-level capture-phase failsafe as defense in depth. Desktop console flash on launch: the CouchDB sidecar spawn already had `CREATE_NO_WINDOW` set, but `couchdb.cmd` is CouchDB's own upstream launcher script and can get a nested child to request its own console regardless of the parent's flags — redirecting all three standard handles to null (the standard mitigation) added in `sync_host.rs`. Also this round: `CustomFieldManager`'s field-type dropdown opened downward and off-screen (always the last row in that modal) — now opens upward like `QuickAdd`'s project picker already does; Settings' Software Updates section tightened (version + check-for-updates merged into one row); `tauri.conf.json` gained `publisher`/`copyright`/`installMode: currentUser` so the installer shows real branding instead of placeholder text and skips the UAC elevation prompt |
| **5.7.8** | **Test release only** — a version bump with no functional change, cut purely to exercise the new updater UX (v5.7.7) a second time end-to-end from a real installed app (check → changelog modal → download progress → explicit restart prompt) |
| **5.7.7** | **Desktop updater UX overhaul** (E3 follow-up, prompted by the first real end-to-end update test in 5.7.6 surfacing how invisible the whole flow was). Settings now shows the running app version (desktop via `@tauri-apps/api/app`'s `getVersion()`, mobile via `@capacitor/app`'s `App.getInfo()` — mobile gets version display only, no update button, since updates there go through the Play Store once C3 ships). New `updateChecker.ts` splits the old single `downloadAndInstall()` call into `check()`/`download(onEvent)`/`install()` (confirmed available on `@tauri-apps/plugin-updater`'s own `Update` type) so the UI can show a real download percentage instead of a blind wait, and so installing is never a surprise: after downloading, a new `UpdateModal.svelte` shows the release notes (see below) and an explicit "Restart to install" / "Later" choice — auto-restart is gone. A silent background check runs every ~6h on desktop and surfaces a small dismissible banner when an update is found, with its own Settings toggle to turn it off entirely for anyone who wants to stay on a version they're happy with (manual "Check for updates" always still works regardless). `latest.json`'s `notes` field was always empty before — `release.yml` now extracts the current version's own CHANGELOG row (new `.github/scripts/extract-changelog-entry.js`) and passes it as `tauri-action`'s `releaseBody`, so the modal's changelog text is the real thing, not a placeholder |
